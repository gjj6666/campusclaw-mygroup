## Purpose

为当前 CampusClaw 提供统一的多应用入口，使新用户登录后无需教师手工创建智能体即可体验课程答疑、解题引导和学习计划，并保持各应用会话、班级资源及现有工具权限边界。

## ADDED Requirements

### Requirement: 多应用目录
系统 SHALL 提供应用中心，至少内置课程答疑、解题引导、学习计划三个具有不同默认角色与用途的 AI 应用，每项展示名称、用途和示例问题。目录 MUST 同时展示本班已启用的自定义智能体，并标识内置来源；其他班级配置 MUST 不可见。应用中心 MUST 提供知识库、提示词模板、技能与工具接入的导航入口，教师管理入口仅教师可用。

#### Scenario: 首次进入平台
- **WHEN** 已登录用户进入没有手工配置智能体的班级应用中心
- **THEN** 可以看到并启动三个内置应用，目录展示各自用途和示例问题

#### Scenario: 本班自定义应用
- **WHEN** 教师创建本班自定义智能体或停用某应用对应的智能体
- **THEN** 目录展示本班已启用的自定义应用，停用的应用不能创建新会话，他班配置不可见

### Requirement: 应用会话与持久配置
系统 SHALL 允许用户一键开始所选内置应用或本班自定义应用的会话。内置应用默认配置 MUST 幂等建立且不覆盖教师已有修改；不同班级 MUST 各自拥有配置，不同用户 MUST 各自拥有会话。应用启动 MUST 不依赖 MCP 或模型网关在线，回答生成仍沿用已有错误呈现。普通启用应用的对话 MUST 继续通过已有检索、技能路由、MCP 鉴权和 SSE 流程。

#### Scenario: 并发首次启动
- **WHEN** 同一班两个用户同时首次启动解题引导应用
- **THEN** 班内只产生一套对应配置与内置技能绑定，每个用户获得独立会话

#### Scenario: 教师配置保留
- **WHEN** 教师修改应用角色、资料和技能后重启项目或再次启动应用
- **THEN** 已保存配置保持有效，不被内置默认值覆盖

#### Scenario: 既有能力回归
- **WHEN** 在应用中绑定本班资料和已发现 MCP 工具技能并提问，然后断开 MCP 再提问
- **THEN** 检索仅使用本班绑定资料，SSE 展示出处及工具状态，审计覆盖成功和 denied，历史会话与原有接口继续可用

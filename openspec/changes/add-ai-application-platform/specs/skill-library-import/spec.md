## Purpose

将既有技能文件解析及导入能力组织为清晰的技能中心，提供可直接安装的内置技能和可校验的自定义文件上传，使教师能独立完成选择、上传、修改及应用绑定而无需编辑项目源码。

## ADDED Requirements

### Requirement: 内置技能安装与维护
系统 SHALL 提供解题引导、知识整理、学习计划至少三个内置技能的目录、用途和正文预览。教师 MUST 能安装为本班技能副本、编辑和绑定到本班智能体；学生 MUST 不能安装或修改技能。内置原件 MUST 不可变，安装 MUST 不覆盖班内同名技能；重复安装 MUST 返回已有副本或明确冲突，不产生静默覆盖。内置应用首次启动所需的可信默认技能 MUST 能由系统幂等配置，不能通过客户端任意内容请求绕过教师写权限。

#### Scenario: 安装内置技能
- **WHEN** 教师安装解题引导并绑定到本班应用
- **THEN** 可读取并修改班内副本，命中适用条件时在会话中生效，修改不影响其他班级或内置原件

#### Scenario: 同名冲突与学生安装
- **WHEN** 教师安装的技能名称已被手工技能占用，或学生调用教师安装接口
- **THEN** 同名冲突明确提示且旧技能不变，学生得到 403

### Requirement: 自定义技能上传
系统 SHALL 提供明确的上传技能操作，接受 UTF-8 编码 .md/.txt 单文件；大小 MUST 不超过 32 KiB，正文 MUST 不超过现有 8000 字限制。上传后 MUST 显示解析预览及保存结果，字段格式继续沿用“名称、适用条件、启用、工具、空行后正文”。扩展名非法、解码失败、无正文、重复字段、非法工具或班内重名 MUST 明确拒绝且不部分保存。MCP 引用 MUST 继续经过本班、连接和发现缓存校验。上传 MUST 不执行脚本、安装依赖、解压归档或读取客户端提供的服务器路径。

#### Scenario: 上传并绑定成功
- **WHEN** 教师上传合法 .md 技能并确认保存，再将其绑定到本班应用
- **THEN** 技能在刷新后仍可读取，学生提问命中时使用保存的正文和合法工具配置

#### Scenario: 上传失败
- **WHEN** 上传超大、编码错误、非法扩展名或引用未连接 MCP 的技能
- **THEN** 显示明确错误，数据库不产生部分技能或关联，不调用未获授权工具

### Requirement: 平台能力验证与可观察性
系统 SHALL 为应用目录、提示词模板和技能安装上传提供 OpenAPI 注解、Swagger 试调及接口测试。验收 MUST 覆盖“选择应用→应用模板→上传并绑定技能→检索知识库→调用真实 MCP→查看审计”的五项能力链路，报告 MUST 区分真实 MCP、模型替身和真实模型环境。模型失败 MUST 显式呈现，MUST 不将其伪装为成功回答；报告及前端 MUST 不包含服务端密钥。

#### Scenario: 五项能力验收
- **WHEN** 执行接口测试及浏览器验收
- **THEN** 可以逐项定位内置应用、模板、知识库、内置/上传技能和 MCP 的证据，并验证原有 Bearer、班级隔离及流式回归；未能完成的环境验证单独记录

## Context

当前仓库只有 OpenSpec 配置、README 和一个尚未应用的相近活动变更，尚无应用代码、数据库模型或部署配置。因此本设计按新建应用能力处理，并把安全边界、班级隔离、材料入库和运行检查作为后续实现必须满足的技术约束。动机和范围见 `proposal.md`。

## Goals / Non-Goals

**Goals:**

- 建立账号密码登录、教师/学生角色、会话和受保护页面访问控制。
- 确保密码只以哈希形式持久化，密钥只从服务端环境变量读取。
- 将用户所属班级作为服务端数据边界，所有材料和知识库查询都强制带班级约束。
- 提供教师上传材料、解析写入知识库、本班列表查询的闭环。
- 拒绝学生上传接口调用，即使学生绕过前端直接发请求。
- 提供 Docker Compose 启动方式和 `GET /health` 运行健康检查。

**Non-Goals:**

- 不实现注册、找回密码、自助加入班级或多班级管理。
- 不实现检索问答、AI 对话、作业提交与批改。
- 不强制具体 Web 框架、ORM、数据库、文件解析库或密码哈希库；但实现必须满足规格中的安全和隔离行为。

## Decisions

1. 服务端身份上下文是唯一授权来源。

   登录成功后，服务端会话或令牌必须能可信地解析出 `userId`、`role` 和 `classId`。材料上传、材料列表、材料详情和知识库读取均从该上下文计算权限，不接受客户端传入的角色或班级作为授权依据。

   Alternatives considered: 由前端保存角色和班级并传给接口。该方案方便页面开发，但无法抵御请求伪造和参数篡改，不满足班级隔离要求。

2. 密码哈希和密钥管理作为启动前置条件。

   用户密码保存时必须先哈希，登录时使用哈希校验。会话签名密钥、数据库凭据、对象存储凭据等敏感配置只能来自服务端环境变量；必需配置缺失时应用不得进入健康可用状态。

   Alternatives considered: 在开发配置或前端环境文件中放默认密钥。该方案启动简单，但容易被提交到仓库或打包进客户端资源。

3. 班级过滤集中在服务层或数据访问层。

   应提供统一查询入口，为材料和知识库记录追加当前用户班级条件。按 ID 读取时也必须同时匹配班级，避免“知道 ID 就能读”的越权路径。

   Alternatives considered: 每个接口手写过滤条件。该方案初期快，但遗漏风险高，尤其后续新增页面时容易绕过。

4. 上传、解析、入库使用一致性边界。

   教师上传成功并不等于知识库可用；只有解析和知识库写入完成后，材料才应在本班可用列表中展示。若采用异步处理，材料必须有明确状态，列表只展示已成功入库的记录。

   Alternatives considered: 上传后立即展示材料记录，再后台补写知识库。该方案反馈快，但会让“本班材料列表能查到知识库记录”的验收变得含混。

5. Docker Compose 是标准本地启动入口。

   Compose 文件应启动应用及其必需依赖，并通过服务端环境变量注入配置。`GET /health` 应尽量只表达运行可用性和关键依赖状态，不暴露敏感配置值。

   Alternatives considered: 只提供本机脚本启动。该方案依赖开发机环境，不利于验收和复现。

## Risks / Trade-offs

- [Risk] 活动变更 `add-class-scoped-material-ingestion` 与本变更范围重叠。→ Mitigation: 本变更包含更完整的安全和运行要求；实施前应选择一个变更作为最终来源，避免重复实现。
- [Risk] 哈希参数或算法选择不当导致安全性不足。→ Mitigation: 使用成熟密码哈希方案，并在测试中确认明文不会落库或出现在响应中。
- [Risk] 班级过滤分散后产生越权读取。→ Mitigation: 封装统一查询入口，并添加跨班级读取测试覆盖 URL、参数和直接 ID 访问。
- [Risk] 文件解析失败导致部分知识库数据可见。→ Mitigation: 使用事务或状态机保证失败记录不进入可用列表。
- [Risk] 健康检查泄露内部依赖细节。→ Mitigation: `/health` 只返回机器可读状态和必要的非敏感信息。

## Migration Plan

- 初始实现可创建用户、班级、材料和知识库表，无需迁移既有业务数据。
- 默认种子账号如需存在，必须通过安全的哈希写入，并通过环境变量或受控初始化流程提供初始凭据。
- Compose 启动前需要准备 `.env` 或等效服务端环境变量文件；该文件不得提交真实密钥。
- 回滚时关闭上传接口和受保护业务入口，保留已入库数据以便审计；若数据库迁移已执行，应按迁移工具提供的回滚路径处理结构变更。

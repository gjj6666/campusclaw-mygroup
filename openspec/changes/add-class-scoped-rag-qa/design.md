## Context

动机见 `proposal.md`，可验收行为见两个 `specs/` 文件。当前 Python 标准库 HTTP 服务使用 SQLite；`knowledge_entries` 每份材料保存一段完整正文，材料按 Bearer 身份的当前班级授权。尚无片段、关键词索引、嵌入调用或生成调用。活动变更 `add-class-scoped-knowledge-search` 提议 Qdrant 和片段溯源，但明确排除生成，且未实施；本变更覆盖其检索范围并增加问答。

## Goals / Non-Goals

**Goals:**

- 让关系库成为正文、班级权限和出处的唯一权威来源，让向量库成为可重建索引。
- 用同一批经过来源复核和相关性筛选的片段支撑检索列表与问答门禁。
- 将真实网关密钥只放在服务端运行环境，兼容项目根目录被 Git 忽略的 `.env`。

**Non-Goals:**

- 不处理图片、OCR、音视频、跨班共享、多轮对话记忆或自动评价答案质量。
- 不要求生成模型在没有本班证据时回答通用知识问题。
- 不改变现有用户、材料和登录凭据语义。

## Decisions

1. **SQLite 保存原文与片段，Qdrant 保存向量。** 新建片段表，记录 `knowledge_entry_id`、`material_id`、`class_id`、`ordinal`、`char_start`、`char_end`、`content`、`index_status` 和索引版本；片段 ID 是向量点的稳定 ID。Qdrant 集合固定维度 2048、余弦距离，并以班级载荷过滤候选；结果返回前再用 SQLite 联合材料、知识条目和片段按当前班级复核。向量点可从关系库重建。备选为仅在向量库保存正文，会让来源和权限事实分散。

2. **分片确定且索引整体可见。** 优先按段落切分，超长段落用字符窗口与小幅重叠，并保存 Python 字符串索引意义下的原文位置；验证原文切片与片段正文一致。先在 SQLite 保存 `pending`，批量向量写入成功后整体置 `ready`；失败整体置 `failed`，不对检索暴露。上传后的原材料仍可查看，响应明确返回检索状态。提供幂等回填/重建命令，避免旧材料缺索引。备选为逐片发布，会造成半份材料被检索到。

3. **关键词和向量采用独立候选，再做混合融合。** 关键词路径在 SQLite 中以归一化词项索引查询：中文生成相邻双字词项，英文按单词切分；只查当前班级的就绪片段并按词项覆盖与频次排序。向量路径调用嵌入网关得到查询向量，再以当前班级过滤 Qdrant 候选，并施加可配置的最低相似度。混合路径对两组有限候选使用倒数排名融合，统一去重、相关性门槛和关系库复核；结果数有上限。关键词模式可在向量依赖故障时独立工作，向量与混合模式返回 503。备选为全库近邻后过滤，存在跨班侧信道且容易让弱近邻冒充证据。

4. **同一网关地址和密钥用于嵌入与对话。** `EMBEDDING_BASE_URL` 只配置到 `/v1`，客户端追加 `/embeddings`；嵌入请求 JSON 只发送 `model` 和 `input`，验证返回 `data[0].embedding` 的长度等于 `EMBEDDING_DIM=2048`。对话使用同一基址和密钥追加 `/chat/completions`，模型独立配置为 `course-chat`；可选的对话地址/密钥覆盖项用于未来拆分网关。启动时从服务端环境读取配置，项目根目录 `.env` 仅填充未由进程环境提供的变量；该文件保持 Git 忽略状态。实际密钥不写入 OpenSpec、`.env.example`、日志或前端。按 UTF-8 编码后的请求体大小限制每次网关调用低于 20MB，超限证据先裁剪或分批。备选为把 `/embeddings` 写进环境变量，容易错误拼接；把维度传给接口则不符合该网关请求契约。

5. **问答 API 是检索服务的受控调用方。** `GET /api/search?q=&mode=keyword|vector|hybrid&limit=` 返回片段、分数、模式与来源。`POST /api/ask` 接收问题，默认混合检索；只有经过相似度/关键词门槛和 SQLite 来源复核的片段非空时，才构造证据编号并调用对话网关。无证据返回 `status=no_evidence, answer="", sources=[]`，不发对话请求。对话提示要求简短、只依证据、在回答中使用证据编号；服务端只接受引用已提供编号且能回到原文的输出，并返回经过复核的 `sources`。未知或缺失引用视为生成失败，不给出貌似有依据的回答。备选为直接相信模型生成的出处文本，无法防止编造引用。

6. **Bearer 授权在入口和来源访问两侧执行。** `/api/search` 与 `/api/ask` 使用已实现的 Bearer 身份，不接受客户端 `class_id` 改变范围；向量候选必须在 SQLite 中再次匹配当前班级和可用材料。页面只接收检索与问答结果，不接触网关密钥；来源链接继续走受保护的材料详情。检索文本作为带界限的资料进入模型消息，不得当成系统指令。备选为直接把模型响应和向量载荷返回前端，会失去服务端出处核验。

## Risks / Trade-offs

- [Risk] 2048 维度或模型版本变更导致新旧向量不可比较。→ Mitigation：启动校验集合维度和版本，版本变化使用新集合并回填后切换。
- [Risk] SQLite 与 Qdrant 无分布式事务，可能出现孤儿向量或待索引片段。→ Mitigation：状态门禁、稳定片段 ID、幂等重试和回填；结果只读 `ready`。
- [Risk] 中文关键词切词与嵌入相关度阈值影响召回。→ Mitigation：固定本班/跨班测试语料，记录命中率并允许服务端调整门槛，不让所有最近邻自动成为证据。
- [Risk] 教学片段可能带有提示注入。→ Mitigation：将其包裹为资料、从不把密钥放进提示，并验证回答引用；模型输出仍需被视为基于证据的辅助内容。
- [Risk] 新网关和向量库增加延迟及运行依赖。→ Mitigation：设置超时、明确 503、限制候选数和请求体大小；关键词模式保持可单独使用。
- [Risk] 现有登录迁移变更的浏览器验收仍未全部勾选。→ Mitigation：RAG 接口沿用当前 Bearer 服务端契约，集成测试覆盖未登录拒绝；上线前完成其剩余浏览器验收。

## Migration Plan

1. 本变更作为检索与问答的唯一实施来源；旧的 `add-class-scoped-knowledge-search` 保持未实施，避免重复执行任务。已有登录工作区改动予以保留，不覆盖。
2. 增加片段表、词项索引、Qdrant 服务及服务端配置；先对演示材料验证回填和双库来源一致性，再开放检索入口。
3. 在被 Git 忽略的 `.env` 中补充用户提供的网关配置，并保持既有变量不变；`.env.example` 仅写占位值。任何测试、日志和响应均不得输出真实密钥。
4. 使用网关替身完成确定性测试；在用户提供的开发网关上做一次受限的嵌入与对话连通性验证，核对维度、引用及无证据零调用。
5. 回滚时关闭检索和问答入口，保留原材料及关系库片段；向量集合可由关系库重建。若网关或 Qdrant 不可用，不返回未经来源复核的生成答案。

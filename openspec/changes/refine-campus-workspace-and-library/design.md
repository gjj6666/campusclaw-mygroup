## Context

动机与功能范围见 proposal.md。当前使用 Python 标准库 HTTP、SQLite 和原生 JavaScript，tutor_page.py 内联大量 CSS，static/tutor.js 同时处理学习对话与教师表单；/materials 另有独立页面。教师配置虽已折叠，仍是一个长面板。会话列表只有标识、助手和创建时间，缺少问题标题。

conversation_attachments 严格绑定用户、班级与原会话，消息 context 只允许 shared/upload；这项限制来自已完成的 add-question-attachments-warm-ui，不能直接解除。用户本次明确同意增加本人跨会话个人资料库。

共享材料已有 subject 字段；分段默认来自 Config（500/80），split_text 保留原文位置。RagService 使用全局 index_version，查询和向量过滤都绑定单版本；直接增加分段表单会让不同策略材料无法一起检索。MCP 已有版本与锁、发现缓存和审计，但只有登记、连接、断开，没有修改/删除。

## Goals / Non-Goals

**Goals:**

以截图的信息架构重组现有能力，保留提问上下文；新增独立个人资料模型；共享资料策略按班配置并兼容已有索引；教师操作具备完整反馈与服务端权限。

**Non-Goals:**

不迁移到前端框架、不拆出新服务、不使用外部资源市场或 Markdown CDN；不增加个人技能跨会话复用、个人向量库、账号管理、聊天删除、错题本、批改或自主学习。已有模型 TLS EOF 不在本次功能修复范围，真实网关验收单独记录。

## Decisions

### 1. 独立页面职责，复用鉴权与业务服务

/tutor 作为学习工作区，通过 #chat 和 #library 切换主模块；/admin 为教师管理壳，学生访问只得到权限提示，教师数据始终由 Bearer API 校验。教师登录后进入 /admin，学生进入 /tutor；教师可在两者间切换。/materials 的 HTML 入口返回以资料模式初始化的新工作区，现有 JSON 形状和老接口保持兼容；新增共享原文端点采用统一404，旧兼容路径不借机扩大本次改造。

拆分工作区、资料阅读、管理台与公共主题/请求工具的页面脚本和样式，不继续向 tutor.js 追加所有管理逻辑。保留现有 HTTP 注解生成路由与 OpenAPI，不另建前端构建链。比较保留长面板的方案：它无法对应截图中的任务分栏，且事件与样式越来越难验证，因此采用明确页面职责。

桌面使用约220px全局导航、260px次级列表和 minmax(0,1fr) 内容区；中等屏幕压缩导航，小屏以可关闭抽屉/模块列表替代并排侧栏。聊天区独立滚动，编辑器始终可操作；空历史显示助手欢迎与快捷问题，第一条问题发送时才创建会话，防止仅浏览助手就产生大量空记录。切换未发送草稿前沿用明确确认流程，生成中禁止切换会话。

无会话时共享/个人选择器使用通用只读清单；“仅本会话”新文件先在内存中严格解码并预览，发送时创建会话、上传暂存文件、取得引用后再发消息。若中途失败，保留已创建会话与上传标识供重试，不重复创建；个人库上传不依赖会话。未发送文件不写入浏览器持久存储。

### 2. 资料浏览和个人库采用不同存储域

新增 personal_materials 表，包含 id、owner_id、class_id、title、filename、subject、content、origin_kind、origin_id、origin_conversation_id、content_hash、created_at。记录不可变，不提供编辑/删除接口，保证旧消息引用仍可读。对相同用户/班级/来源及内容哈希的复制幂等；普通上传可保留不同命名的副本。所有来源读取先检查身份与班级，不使用请求中的 owner_id/class_id。

新增 GET/POST /api/personal-materials、GET /api/personal-materials/{id}。创建输入严格三选一：filename/content/subject，或来源 shared 的材料 id，或来源 attachment 的 id 与 conversation_id。共享复制读取当前可访问原文；附件复制必须是本人原会话的 material 类型。来源不可访问统一404；类型、编码、大小与字符超限400，不静默截断。文件上限沿用32 KiB、12000字。共享和附件保留原记录，本次不自动迁移历史私有附件。

资料区按现有 subject 分组，不从文件名臆造多级目录。共享列表新增安全只读 /api/library/materials 和 /api/library/materials/{id}，返回学科、标题、状态与受保护正文；个人列表只返回本人本班。复制按钮“保存到我的资料”形成独立正文快照，不新增共享关系表或共享搜索权限。教师只能读取自己的个人库，不可借管理台查看学生个人库。

### 3. 扩展每轮引用，保持会话附件契约

context.materials 新增 {source:'personal',id}，私有技能仍只接受 shared/upload。扩展解析器与选择清单而不重解释 upload：个人引用校验本人/班级/当前会话归属，原 upload 继续要求原会话；共享引用继续检查启用/就绪条件。最多三份资料，个人与上传正文合计18000字，缺省/null/空列表的原语义保留。

个人正文直接以数据加入用户消息，不调用嵌入或写入 Qdrant。与共享、附件来源合并编号 S1…；新增 kind:'personal'、personal_material_id 和受保护URL，快照保留 source、id、名称，历史读取继续检查会话归属。问题旁的上传明确选择“仅本会话”或“个人资料库”，技能上传仅提供前者；资料阅读区可保存到个人库并回到问题选择，不自动调用模型。

### 4. 安全阅读与可记忆界面状态

为 Markdown 实现小范围安全渲染（标题、段落、列表、行内/块代码、普通链接）；使用 DOM 创建文本节点，禁止原始 HTML、脚本和事件属性，不自动发起外部图片请求。链接仅允许 http/https，外链使用安全 rel 属性。纯文本按原样换行，超长正文有阅读滚动区。

主题使用公共 CSS 变量和 data-theme，默认暖米白/砖红，深色为暖深棕配浅文字；localStorage 只存主题和列表/网格偏好，Bearer 继续放 sessionStorage，不保存文件或令牌到偏好。通过首屏主题脚本减少闪烁。两套主题都实测对比度、键盘焦点、禁用和错误状态，保留 reduced-motion 支持。

会话列表接口追加 title、last_activity、agent_name：在本人本班范围内以 SQL 获取首条用户问题前30字和最近消息时间，空会话标题“新对话”，按最近活动倒序。保留原字段，避免前端每个会话单独加载消息；显示时间统一按浏览器本地时区解释服务端 UTC。

### 5. 管理台复用现有写接口，新增最小管理能力

五个分栏各自加载，保留已加载表单草稿，按对象跟踪 dirty 状态；切换编辑对象/页面时给出保留或放弃选择，网络错误不清空输入。学生分栏仅新增 GET /api/admin/students，筛选本班 role=student，仅返回 id/username，不新增任何账号写接口。智能体、模板、技能安装与共享上传复用现有接口；共享资料真实文件上传先解码，再传原 filename/content/subject，不把学生个人上传转到教师接口。

新增 PUT/DELETE /api/mcp/servers/{id}，编辑仅允许 base_url、auth_token；名称不可改，令牌省略/空字符串保留，非空按原规则校验。有效配置变化在锁内断开、增版本、清工具；没有实际变化不无故断开。删除有前端确认，清理服务器和缓存，审计保留（原审计无服务器外键）。

新增不可复用的状态代号，登记和连接配置状态变化时更新；进行中调用重新检查代号、版本和存在性。删除/修改竞态使旧结果变为 denied 并落审计，不能因 _get 的404逃逸而漏审计，也不能因删除后重登复用标识接受旧调用。名称引用在移除后不自动改写旧技能，保存失败或运行 denied 都有明确提示。

### 6. 班级分段策略和材料索引版本

新增 class_index_policies（class_id、规范化策略JSON、revision）及 material_index_states（material_id、已应用策略快照、active_version、embedding_signature、状态、last_error）。无策略的班级使用部署 Config 默认，不把截图中的800/80强加给旧数据。自动模式沿用原分段；自定义支持空行/换行/句末边界，长度100–2000，重叠0–40%，重叠字符数为 floor(size*ratio/100)，必须推进游标。

清理只处理片段边界空白，不改写原文内部字符；长单元硬切并保留有序位置，保证 source[start:end]==chunk.content。预览与正式分段使用同一纯函数，预览返回总数、前20段及是否还有更多的显式标记，不写数据库或访问嵌入。新增 GET/PUT /api/admin/index-policy、POST /api/admin/index-policy/preview、GET /api/admin/materials（含索引状态）、POST /api/admin/materials/{id}/reindex。全部教师限定、班级来自鉴权。

保存策略只更新班级策略revision。新上传和指定重建捕获当时策略与嵌入配置快照；处理中保存新策略不改变进行中任务，完成后可显示仍待按新策略重建。同材料重建锁返回409；重建同步响应真实结果，前端显示处理中并可刷新状态，不提供虚构百分比。原文始终保留；更新片段前将其置 pending，失败标记 failed 并提供重试，本次不承诺重建期间旧索引持续可用。

新 active_version 指纹包含嵌入签名、分段策略与实现版本。检索由全局单版本改为每份材料当前 active_version：SQL 和最终原文验证严格匹配材料当前状态与版本；Qdrant 仍按班级与材料范围过滤，再使用本班兼容的当前版本集合过滤，返回后必须再做 SQLite 授权核验。兼容旧单字符串版本参数，扩展版本集合查询供新路径使用。旧向量清理失败不能让被替换版本进入结果。

迁移为已有材料从现有 chunk 版本及状态建立索引元数据，不强制重算；兼容当前嵌入签名的旧 ready 片段继续可检索，不同策略可同时存在。嵌入配置不兼容时明确提示需重建，不将不兼容向量当作正常索引。个人资料与会话附件均不进入此策略或全班检索。

## Risks / Trade-offs

- 全局版本改为材料版本可能误放旧片段 → Qdrant 版本集合过滤加 SQLite 当前版本、状态、归属与原文位置最终校验，测试旧代、跨班、伪造向量结果。
- 重建中该资料暂不可检索 → 清晰 pending/failed 状态、原文可读、单份重试，不把修改配置等同于成功重建。
- 个人副本扩大存储使用 → 沿用文本大小限制、来源复制幂等；不引入全文编辑或隐式复制，不承诺本次实现配额/删除生命周期。
- 新导航丢失草稿 → 分离模块状态、识别异步返回所属会话，切换确认与失败保留均有浏览器验证。
- Markdown 注入与外链泄露 → 严格安全子集、文本节点构造、不加载远程图片，并验证危险文件名、正文与URL。
- 原有真实模型不可用掩盖问题 → 使用替身模型/嵌入与真实MCP完成确定性验收，真实Compose的索引和对话另记成功或失败，不降低TLS校验。

## Migration Plan

实施前备份运行数据库与向量卷。增量创建个人库、策略和材料索引状态表，并为 MCP 状态代号赋值；初始化可重复执行，旧资料、技能、绑定、会话、附件与审计保持。先完成后端兼容与权限，再替换页面；旧 JSON 契约和旧 context 缺省路径回归通过后重建 Compose。

以单元测试验证分段/迁移/复制/版本边界，以隔离 HTTP 测试验证双角色跨会话复用、404/403、索引失败重试、MCP 修改删除竞态及 SSE。浏览器验证教师五栏、学生主流程、深浅主题、Markdown安全、桌面与390像素布局。HTML报告与截图留在 Git 忽略目录，文档记录真实网关结果。

回滚应用时可保留新增个人库表，但旧代码不能理解 personal 来源及多策略索引，因此完整回滚必须同时恢复数据库和向量卷备份；不能仅回退代码后宣称检索兼容。
